# Демонстрационные задания

Корневой каталог заданий мини-курса. Каждое задание — **самодостаточный каталог**
`<категория>/<имя>`: его можно скопировать или выгрузить архивом, и оно не зависит
ни от соседних заданий, ни от остального репозитория. Каталог категории создаётся
вместе с первым заданием в ней (`make task-new`); пока все задания лежат в коллекции
`lecture-1`.

```
project/tasks/
├── tasks.yml          формат флага, категории, уровни сложности, коллекции
├── _template/         шаблон задания
├── _tools/taskctl.py  создание, проверка, экспорт, запуск, verify
└── lecture-1/         коллекция: короткий CTF вводной лекции (см. ниже)
```

## Коллекции

Коллекция — подкаталог, объединяющий задания одной лекции (короткий CTF). Внутри
коллекции каталог задания называется `<N>-<категория>-<имя>` (`1-web-portal`,
`2-crypto-oracle`): `<N>` — порядковый номер задания в лекции (совпадает с полем `order`),
`id` в `task.yml` — имя каталога без номера, а категория берётся из поля `category`. Коллекции
перечислены в `tasks.yml` (ключ `collections`). Путь задания в командах — либо
`<категория>/<имя>` (обычное задание), либо `<коллекция>/<N>-<категория>-<имя>`.

Кроме заданий коллекция `lecture-1` содержит служебные каталоги: `checker/` (проверщик
флагов, только для лектора), `docs/` (инструкции по установке), а также `docker-compose.yml` (локальный запуск сервисов
студентом) и `docker-compose.lecturer.yml` (боевой стенд лектора).

## Структура задания

```
<категория>/<имя>/
├── task.yml           метаданные: название, сложность, очки, флаги, сервис
├── README.md          условие для участника
├── public/            файлы, выдаваемые участнику
├── src/               исходники и генераторы (участнику не выдаются)
├── deploy/            задание с сервисом: Dockerfile, docker-compose.yml,
│   ├── ...            flags.env.defaults — флаги по умолчанию (контейнер читает из окружения)
└── solution/
    ├── README.md      разбор для преподавателя
    ├── writeup.md     разбор для студента (выдаётся позднее)
    └── solve.py       эталонное решение, печатает все флаги (по одному в строке)
```

### Условие (README.md)

Все условия оформляются одинаково, как в `_template/README.md`: заголовок, строка
«Категория · Сложность · очки», легенда абзацем без заголовка, затем общие блоки —
**Доступ**, **Файлы**, **Инструменты**, **Локальный запуск**, **Формат флага** — именно
в таком порядке и жирным шрифтом, а не заголовками Markdown; неприменимые блоки
опускаются. В условии нет подсказок к решению и напоминаний «ищите остальные флаги дома».

### Несколько флагов

Основной флаг — поле `flag` (это флаг №1). Дополнительные — список `flags`, элементы
с полями `id`, `flag` и необязательными `points`, `title`, `hidden` (не выносится на
слайды), `env`. Все флаги соответствуют формату из `tasks.yml`; `solve.py` печатает
каждый из них по одной строке (в том числе скрытые).

### Флаги по умолчанию и боевые (поле `env`)

Флаги бывают двух видов:

- **времени выполнения** — их отдаёт контейнер; в `task.yml` у такого флага указано
  `env: ИМЯ_ПЕРЕМЕННОЙ`. Умолчания лежат в `deploy/flags.env.defaults`
  (`BootCTF{default_...}`, выдаются студентам для локального запуска) и совпадают со
  значениями в `task.yml`. Боевые значения лектор задаёт в `flags.real.env` коллекции
  (в Git не входит; шаблон — `flags.real.env.example`), они переопределяют умолчания.
- **файловые** — зашиты в выдаваемый файл (дамп, образ, ELF, архив), одинаковы для
  всех; у них нет `env`, и это значение — боевое.

Правила:

- имя каталога — строчная латиница, цифры и дефис; `id` совпадает с именем каталога,
  `category` — с каталогом категории (в коллекции — с префиксом имени);
- всё необходимое лежит внутри каталога задания: без ссылок на файлы вне его;
- файлы из `public/` воспроизводимо получаются из `src/` (генератор, фиксированное зерно);
- файловый флаг не встречается открытым текстом в `README.md`, `public/` и выдаваемых
  каталогах (`handout`) — исключение `flag_in_public: true`;
- `handout` перечисляет каталоги, выдаваемые студенту помимо `README.md` и `public/`
  (например, `deploy` — чтобы поднять сервис локально);
- задание с сервисом запускается одной командой `docker compose up` из `deploy/`,
  порт указан в `task.yml`; флаги читаются из окружения (`flags.env.defaults`).

## Команды

Выполняются из корня репозитория (нужны Python 3 и PyYAML):

```sh
make task-new TASK=crypto/xor-intro          # создать из шаблона
make task-new TASK=lecture-1/1-web-portal      # то же в коллекции (категория из префикса)
make tasks-list                              # список заданий
make tasks-check [TASK=<путь>]               # проверка структуры и метаданных
make tasks-verify [TASK=<путь>]              # поднять сервис и сверить solve.py со всеми флагами
make task-export TASK=crypto/xor-intro       # архивы одного задания
make tasks-export                            # архивы всех заданий
```

`make tasks-verify` для задания с сервисом поднимает его (флаги по умолчанию),
запускает `solution/solve.py` и сверяет вывод со всеми флагами из `task.yml`. Решение
выполняется системным `python3`; нужные инструменты и библиотеки коллекции `lecture-1`
перечислены в `lecture-1/docs/install-linux.md`.

Экспорт одного задания создаёт в `public/tasks/` два архива:

| Архив | Содержимое | Для кого |
|---|---|---|
| `<категория>-<имя>.zip` | `README.md`, `public/`, каталоги из `handout` | участники |
| `<категория>-<имя>-full.zip` | каталог целиком, включая `src/`, `deploy/`, `solution/` | преподаватель, организаторы |

Перед экспортом задание проходит ту же проверку, что и `make tasks-check`.

## Короткий CTF лекции (коллекция)

Команды для коллекции `lecture-1` (нужен Docker):

```sh
make lecture-up LECTURE=01-intro     # боевой стенд: все сервисы + checker, флаги из flags.real.env
make lecture-down LECTURE=01-intro   # остановить стенд
make lecture-export LECTURE=01-intro # комплект для студентов
```

`make lecture-up` требует `flags.real.env` в каталоге коллекции (скопировать из
`flags.real.env.example`, вписать боевые флаги) и поднимает сервисы с `BIND=0.0.0.0`.
`make lecture-export` заново собирает `public/export/<лекция>/` из трёх файлов:

| Файл | Содержимое |
|---|---|
| `<лекция>.pdf` | слайды лекции без заметок докладчика |
| `<лекция>-tasks.zip` | условия заданий, `public/`, выдаваемые каталоги (`handout`), `docs/` и общий `docker-compose.yml` |
| `<лекция>-writeups.zip` | разборы для студентов (`solution/writeup.md`), выдаются после занятия |

Боевые флаги, `src/`, разборы для преподавателя, `solve.py` и проверщик в комплект не
попадают, а экспорт прерывается, если боевой флаг просочился в собранные файлы.
