# Решение: Турникет (pwn)

**Идея.** Простейшее переполнение буфера на стеке с перенаправлением выполнения
(ret2win). Защиты намеренно отключены: нет стековой канарейки, нет PIE. Задание
учит трём вещам: найти уязвимое чтение в исходнике, вычислить смещение до адреса
возврата, передать управление на нужную функцию.

Флаг один, времени выполнения: `win()` печатает значение `PWN_FLAG_1` из окружения
сервера. Боевое значение задаёт преподаватель в `flags.real.env`, бинарь не меняется.

## Ход решения

1. **Статический разбор.** В `gatekeeper.c` функция `check()` объявляет `char buf[64]`
   и читает в него до 256 байт: `read(0, buf, 256)` — переполнение. Рядом есть
   функция `win()`, печатающая флаг, но из `main()` она не вызывается.

2. **Защиты.** `pwn checksec` / баннер `ELF()`:

   ```
   Arch:       amd64-64-little
   RELRO:      Partial RELRO
   Stack:      No canary found     ← канарейки нет: перезапись адреса возврата не ловится
   NX:         NX enabled          ← шелл-код на стеке не исполнить, но он и не нужен
   PIE:        No PIE (0x400000)   ← адрес win() фиксирован, ASLR кода нет
   Stripped:   No                  ← символ win виден: nm/ELF().symbols['win']
   ```

3. **Смещение.** Буфер 64 байта + 8 байт сохранённого `rbp` = **72** байта до адреса
   возврата. Проверяется цикликом (`cyclic`/`cyclic_find`) либо прямым подбором:
   payload из 72 «A» и адреса `win` (`0x401186`) срабатывает.

4. **Выравнивание стека.** `win()` печатает флаг системным вызовом `write()`, а не
   `printf()`, поэтому инструкции `movaps` не выполняются и прыжок прямо на `win()`
   надёжен — ret-гаджет для до-выравнивания не нужен. Это сознательное упрощение.

5. **Эксплойт** (`solve.py`): `b"A"*72 + p64(elf.symbols["win"])`. Против живого стенда:

   ```console
   $ TASK_HOST=127.0.0.1 python3 solution/solve.py
   BootCTF{default_pwn_1}
   ```

## Подсказки по нарастающей

1. Сравните размер буфера в исходнике с числом читаемых байт.
2. Что лежит на стеке сразу за буфером? Что произойдёт при возврате из `check()`?
3. В программе есть функция, которую никто не вызывает. Посмотрите её адрес: `nm gatekeeper | grep win`.
4. Смещение до адреса возврата — 72. Соберите `"A"*72 + p64(win)`.

## Типичные затруднения

- **Забыли про сохранённый `rbp`** и берут смещение 64 вместо 72.
- **Прыжок на `win()` «падает»** — в задачах с `printf` это ошибка выравнивания стека
  (`movaps`); лечится лишним ret-гаджетом. Здесь `win()` на `write()`, проблемы нет —
  полезно показать разницу.
- **Локальный флаг не совпадает с аудиторным** — это нормально: локально действует
  умолчание, боевое значение — только на стенде преподавателя.

## Что показать на демонстрации

`checksec` → строки `check()`/`win()` в исходнике → `nm` с адресом `win` → сборка
payload в pwntools и запуск против локального контейнера. Связь со слайдами раздела pwn.
