# Решение: Портал (web)

**Идея.** Задание проводит через базовые приёмы веб-категории: чтение исходного кода
страницы и клиентских скриптов, ручную отправку HTTP-запросов с заголовками, осмотр
заголовков ответа и внедрение в шаблон на стороне сервера (SSTI). Шесть флагов —
по одному приёму на каждый; четыре разбираются на лекции, два оставлены на дом.

Все флаги — времени выполнения: сервис читает их из окружения при старте. Значения
ниже — умолчания локальной копии (`BootCTF{default_...}`); на боевом стенде флаги
другие. Эталонное решение `solution/solve.py` печатает все шесть.

## Флаги и приёмы

| № | Где | Приём | Когда |
|---|---|---|---|
| 1 | base64 в HTML-комментарии `note-01` на `/` | просмотр исходного кода, `base64 -d` | лекция |
| 2 | массив кодов символов в `/js/app.js`, хоткей Ctrl+Shift+Y | чтение JS / DevTools | лекция |
| 3 | `/api/secret` (указан в `/robots.txt`): POST с заголовком `X-Audit-Token: lighthouse` | `curl -X POST -H` | лекция |
| 4 | форма «Как вас зовут?» на `/` → `/hello?name=` — SSTI, `{{config}}` раскрывает `AUDIT_NOTE` | шаблонная инъекция | лекция (демо) |
| 5 | заголовок ответа `X-Lighthouse-Note` на `/` | `curl -i` | дом (скрытый) |
| 6 | `/flag.txt` в контейнере — только через SSTI → выполнение кода | SSTI → RCE | дом (скрытый) |

## Полное решение

1. **Флаг 1.** В исходнике `/` есть комментарий `<!-- note-01: <base64> -->`.
   `curl -s http://<host>:8001/ | grep note-01`, затем `base64 -d`.
2. **Флаг 2.** В `/js/app.js` объявлен массив `note = [66, 111, ...]` (коды символов) и
   обработчик `keydown` на Ctrl+Shift+Y, показывающий `String.fromCharCode(...)`.
   Нажать хоткей в браузере либо собрать строку из кодов вручную.
3. **Флаг 3.** `/robots.txt` запрещает `/api/secret`. `GET` возвращает 405, `POST` без
   заголовка — подсказку про `X-Audit-Token`, `POST` с `X-Audit-Token: lighthouse` — флаг.
4. **Флаг 4.** Форма на главной отправляет имя на `/hello?name=X`; страница приветствия подставляет имя в шаблон без экранирования. `{{7*7}}` даёт
   `49` (признак SSTI), `{{config}}` печатает конфигурацию приложения с ключом `AUDIT_NOTE`.
5. **Флаг 5 (скрытый).** На `/` сервер добавляет нестандартный заголовок ответа
   `X-Lighthouse-Note`. Виден в `curl -i` или во вкладке «Сеть» DevTools.
6. **Флаг 6 (скрытый).** SSTI из флага 4 доводится до выполнения кода:
   `{{ cycler.__init__.__globals__.os.popen('cat /flag.txt').read() }}` читает
   `/flag.txt` в контейнере. Показывает, что SSTI — это не просто `{{7*7}}`, а полноценное
   удалённое выполнение кода.

## Заметки по стенду

Пояснения, намеренно убранные из выдаваемого студентам `deploy/` (там они были бы подсказками):

- флаг 6 приложение пишет в `/flag.txt` при импорте модуля, поэтому в `Dockerfile`
  один рабочий процесс gunicorn, а в `docker-compose.yml` не включён `read_only`;
- флаг 4 лежит в `app.config["AUDIT_NOTE"]`, флаг 5 добавляется в `after_request`
  только для пути `/`.

## Лесенка подсказок (флаги лекции)

- **Флаг 1.** «Вы всё ещё в браузере — а что отдаёт сервер на самом деле?» →
  «Посмотрите исходный код страницы (Ctrl+U)» → «Строка вида `base64` в комментарии».
- **Флаг 2.** «Страница подгружает скрипт» → «Откройте `/js/app.js`» →
  «Что делает обработчик нажатия клавиш и что за массив чисел?».
- **Флаг 3.** «У сервиса есть служебные адреса» → «Загляните в `/robots.txt`» →
  «GET запрещён; попробуйте POST, сервер подскажет про заголовок».
- **Флаг 4.** «Портал здоровается по имени» → «Что будет, если передать `{{7*7}}`?» →
  «Это SSTI; попробуйте `{{config}}`».

## Типичные затруднения

- путают кодирование и шифрование: base64 — это кодирование, «расшифровывать» нечего;
- в `curl` забывают `-X POST` или кавычки вокруг заголовка;
- браузер экранирует `{` `}` в адресной строке — удобнее слать SSTI через `curl` с
  URL-кодированием (`%7B%7B...%7D%7D`);
- флаг 2 ищут на сервере, хотя он целиком на стороне клиента (в JS).

## Порядок живой демонстрации

Рекомендуется: флаг 1 (просмотр исходника) → флаг 3 (`curl` с заголовком) →
флаг 4 (SSTI, довести до `{{config}}`). Флаги 2, 5, 6 обозначить и оставить на дом.
