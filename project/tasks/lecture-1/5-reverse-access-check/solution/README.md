# Решение: Пропуск (reverse)

**Идея.** Одна небольшая утилита демонстрирует три базовых приёма обратной
разработки: извлечение открытых строк, наблюдение за программой в отладчике и
статический разбор логики проверки. Три флага проверяются независимо; любой из
них даёт `Access granted`.

## Разбор по флагам

### Флаг 1 — открытая строка (`strings`)

Сравнение идёт через `strcmp` с константой `FLAG1`, поэтому флаг лежит в секции
`.rodata` открытым текстом.

```console
$ strings access-check | grep BootCTF
BootCTF{str1ngs_unlock_the_d00r}
```

### Флаг 2 — XOR и конструктор (`gdb`)

Флаг хранится в массиве `enc2`, зашифрованный однобайтовым XOR (ключ `0x5a`).
Функция с атрибутом `constructor` расшифровывает его в `dec2` **до** `main`, а
сверка идёт ручным побайтовым циклом (не `strcmp`/`memcmp`), поэтому `ltrace`
ничего не покажет. Достаточно остановиться в начале `main` и прочитать `dec2`:

```console
$ gdb -q ./access-check
(gdb) break main
(gdb) run
(gdb) x/s &dec2
0x4040e0 <dec2>:	"BootCTF{gdb_sees_the_c0nstruct0r}"
```

Альтернатива без отладчика: прочитать `enc2` из файла и перебрать 256 значений
ключа до появления префикса `BootCTF{` — так делает `solution/solve.py`.

### Флаг 3 — цепочка if-ов (статический анализ, домашнее)

Здесь нет ни строки, ни цикла: `check3` сравнивает каждый символ ввода отдельным
`if`, а условия в исходнике перемешаны, поэтому «сверху вниз» флаг не читается.
В дизассемблере каждое условие — пара инструкций:

```asm
mov    -0x18(%rbp),%rax      ; указатель на ввод s
add    $0x20,%rax            ; s + 0x20  -> индекс 32
cmp    $0x7d,%al             ; сравнение с '}' (0x7d)
```

Нужно собрать пары «индекс → символ» и упорядочить по индексу. Проверка длины
(`cmp $0x21,%rax`, 0x21 = 33) подсказывает длину флага. Эталонный разбор
(`solve.py`) делает это через `objdump`.

## Как вести на занятии

- Флаг 1 — показать `strings … | grep BootCTF` вживую (1–2 минуты).
- Флаг 2 — показать `gdb`: `break main`, `run`, `x/s &dec2`. Подчеркнуть, что
  конструктор отработал до `main`, а `ltrace` бесполезен из-за ручного цикла.
- Флаг 3 — оставить на дом: объяснить идею (перемешанные условия) и показать
  один-два `cmp` в `objdump`, дальше студенты собирают строку сами.

## Ступенчатые подсказки

1. Пропусков три, а не один; проверяйте все ветки.
2. Флаг 1: чем смотрят печатные строки в файле?
3. Флаг 2: в файле его нет открытым текстом — значит, он появляется во время
   работы. Что выполняется до `main`? Остановитесь в `main` и посмотрите память.
4. Флаг 3: ни строки, ни цикла. Каждый символ сравнивается своим `if`. Соберите
   условия из дизассемблера и упорядочьте по индексу символа.

## Типичные затруднения

- Студенты останавливаются на первом флаге, решив, что задание решено.
- Для флага 2 пробуют `ltrace` и не видят сравнения (цикл ручной) — это и есть
  повод заглянуть в `gdb`.
- Для флага 3 пытаются читать условия подряд; важно заметить индекс в `add`.

Эталонное решение печатает все три флага:

```console
$ python3 solution/solve.py
BootCTF{str1ngs_unlock_the_d00r}
BootCTF{gdb_sees_the_c0nstruct0r}
BootCTF{static_1f_ladder_at_h0me}
```
