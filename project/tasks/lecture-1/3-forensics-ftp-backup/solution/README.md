# Решение: Резервная копия (forensics)

**Идея.** Протокол FTP передаёт и управляющий канал (команды, учётные данные), и
данные открытым текстом. По дампу одного сеанса восстанавливаются и пароль входа, и
сами файлы. Один из файлов — защищённый паролем ZIP-архив, но ZipCrypto не шифрует ни
имена файлов, ни комментарий архива, а короткий пароль подбирается по словарю.
Задание учит двум базовым навыкам forensics: читать сетевой дамп и работать с
метаданными архивов.

Четыре флага:

| № | Где | Приём | Когда |
|---|---|---|---|
| 1 | `notes.txt`, переданный открыто | Follow TCP Stream / `tshark` | на лекции |
| 2 | комментарий архива `backup.zip` | `unzip -z` / `zipinfo` | на лекции |
| 3 | `flag.txt` внутри зашифрованного архива | подбор пароля по словарю | дома (или на лекции) |
| 4 | каталог на живом сервере, куда сеанс не заходил | вход по подслушанному паролю | дома (скрытый) |

## Два маршрута к файлам

Файлы `notes.txt` и `backup.zip` можно получить **двумя способами**, и на лекции
полезно показать оба:

1. **Из дампа.** В Wireshark: `File → Export Objects` недоступен для FTP, поэтому
   используем `Follow TCP Stream` на каждом потоке данных (их видно по командам `PASV`
   + `RETR` в управляющем канале) и сохраняем поток как сырые байты.
2. **С живого сервера.** В управляющем канале пароль виден открытым текстом — входим
   им на `<host>:21` и забираем те же файлы обычным FTP-клиентом.

## Подслушанные данные

В дампе два узла: клиент `10.10.20.23` и FTP-сервер `10.10.20.5` (дамп снят в отдельной
сети Docker, см. `src/capture/`). Управляющий поток (порт 21, Wireshark сам распознаёт его как FTP) содержит:

```
USER lighthouse
PASS Harbor-2026
```

Эти учётные данные открывают и живой сервер (флаг 4). Пароль ZIP-архива — отдельный,
он нигде в дампе не передаётся и подбирается по словарю (это слово `dragon`).

## Разбор по флагам

**Флаг 1 — `notes.txt` в открытом трафике.** Поток данных с `notes.txt` читается
напрямую; флаг — в тексте заметки. На лекции удобнее всего `Follow TCP Stream` в
Wireshark. В `tshark` то же делает `-z follow,tcp,ascii,<номер потока>`. Значение:
`BootCTF{ftp_traffic_in_clear}`.

**Флаг 2 — комментарий архива.** ZipCrypto шифрует только содержимое файлов. Имена и
комментарий архива остаются открытыми: `unzip -z backup.zip` печатает комментарий —
это и есть флаг `BootCTF{zip_comment_not_encrypted}`.

**Флаг 3 — пароль архива по словарю.** Внутри `backup.zip` лежит `flag.txt`, но он
зашифрован. Пароль — словарный, подбирается по `password.lst`:
`fcrackzip -D -p /usr/share/john/password.lst -u backup.zip` находит `dragon`, после
чего `unzip -P dragon` отдаёт `BootCTF{zip_password_from_wordlist}`. Классический путь
`zip2john backup.zip > h; john --wordlist=... h` здесь не запускается: в пакете
Debian `john` нет утилиты `zip2john`, поэтому в стенде используется `fcrackzip`
(в полной сборке John Jumbo `zip2john` есть, об этом можно упомянуть).

**Флаг 4 — скрытый, на живом сервере.** Входим подслушанными `lighthouse` /
`Harbor-2026` на `<host>:21`. Сеанс из дампа забрал только `notes.txt` и
`backup.zip` из корня и в каталог `archive/` не заходил. Там, в `archive/old/`,
лежит `handover.txt` со скрытым флагом (на локальной копии —
`BootCTF{default_forensics_hidden_dir}`, на боевом стенде — свой).

## Порядок живой демонстрации

1. Открыть дамп в Wireshark, показать управляющий канал и пароль открытым текстом.
2. `Follow TCP Stream` на потоке с `notes.txt` → флаг 1.
3. Сохранить поток с архивом, `unzip -z` → флаг 2.
4. Коротко показать, что содержимое архива зашифровано, и оставить подбор пароля и
   живой сервер на дом.

## Подсказки по нарастающей

1. «Чем передаётся FTP — и что из этого шифруется?»
2. «У соединения FTP два канала: команды и данные. Данные идут отдельным TCP-потоком.»
3. «Комментарий и имена файлов в ZIP не шифруются даже при пароле.»
4. «Пароль архива — короткое словарное слово. Пароль входа на сервер вы уже видели.»

## Типичные затруднения

- Пытаются «расшифровать» ZIP вместо подбора пароля по словарю.
- Ищут файлы в управляющем потоке, не замечая отдельных потоков данных (`PASV`).
- Путают пароль FTP (виден в дампе) и пароль архива (подбирается).
- На живом сервере не осматривают вложенные каталоги (`archive/old/`).

Решение `solution/solve.py` печатает все четыре флага: 1–3 из дампа, 4 — с живого
сервера (`TASK_HOST`/`TASK_PORT`).
